## 5. Semantic bugs

Two production-code semantic bugs were found during
close-out; both are fixed, and each now carries a pin the
old behavior fails:

- 180° folds built from two 90° arcs left arc-arc tangent
  joints the C07 checker cannot certify (`edge-face-
  uncertain`, not `ok:`). The profiles now use single
  180° arcs per side, which the kernel's own splitter
  (`splits_go`, built for exactly this: the `hw` half
  flag, axis-crossing splits) lowers internally with no
  edge-edge tangent joints. 180° folds now check `ok:`
  (10 faces, 2 cylinders, same volume/bbox). Pins
  `counts_k2` (7/8) and `arcs_all` (2/2/4/0) fail on the
  two-arc tables.
- `rot180` rotated profile points but left arc-segment
  centers unrotated, so every -x variant (edges 2/3)
  failed with `arc-start-off-circle`. Rotation now maps
  centers too (`sg_rot`/`segs_rot`); orientation and
  ccw flags are preserved (det +1). Pins `rot_k0`
  (5.0/45.0 bits) and `rot_k2` (5.0/5.0 bits) fail on
  the unrotated centers.

Further audit trail (harness/spec, no production change
except where noted):

- One C-backend fault bisected during the build: growing
  `op_of_feat` to 13 branches fails `bend -o` with an
  arity-over-247 fault while the JS backend emits fine
  (upstream `bendlang/bend#1069`, `WIDE=247` live values
  in `emit_clo`). Fixed by the split sheet dispatch in
  §4 (production change, behavior-preserving for all
  existing ops; proven by the 882/882 regression).
- Intent material rule documented (contract §2):
  `create` for flat, `add` for every bend/hem (each
  stores strictly more volume than its base at R/T ≥ 1).
- The F1 mutant site had to be anchored to the full
  `sh180up` body: the 90° and 180° profiles share
  identical seg-index text (same combinatorics, only
  point coordinates differ), so the seg-only site
  matched twice.
- Suite-only repairs, each re-run green: `geom_type`
  property (not a method), two record-kwarg collisions,
  numpy→JSON scalar wrapping, the reopen assertion
  (nodes print as `n0.*`; now asserts 16 `loops=` lines
  + volume containment).
