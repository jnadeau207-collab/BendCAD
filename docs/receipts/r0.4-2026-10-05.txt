## 2. Findings and repairs

Every finding was confirmed on the predecessor's code, by a probe
wherever behavior is at stake, and every semantic repair has a law
that the predecessor fails (§3).

F1  C06 hole clearance (`hole_clr_pt`, `hole_hh`, `hole_rect`) claimed
    exact expansion arithmetic but formed each coordinate difference
    with a rounded `F64.sub`. Probe: `hole_clr_pt(2^60+512, 1, 255, 0,
    255, 2, 2^60+256)` returned 2 (tangent); the exact answer is 0
    (clear). Repair: `E.ex_dif` for every difference (`ex_d2`, `ex_dot3`).
F2  C06 `qframe` gave left-handed frames on `-X`, `-Y`, `-Z` while the
    Gram–Schmidt branch is right-handed (`n1 × n2 = a`). Repair: on a
    world axis `n2` carries the axis component's sign.
F3  C06 profile checks (`simp_*`, `pr_*`, `hh_*`) looked points up by
    position inside double loops, `O(n³)`. Repair: segment lists walked
    in the same order, so every reported code is unchanged.
F4  About a hundred unreachable C06 definitions (the spec-join machinery,
    `*_new`, `rect_loop`, `f_nth`, `iv_nth`, `gval_def`, `hole_boss_go`,
    `hole_clr_hs`, `gid`, `qf_show*`), the leftover R0.2 C04 helpers
    `h{lp,fa,so}_nodup_c`, and dead C01/C03 helpers (`fin_or_unc_d/p`,
    `hpt_fin`, `gate_dom`) were removed. `VOrbit` stays: the C04
    reference oracle (`tools/oracle/c04/ref/ops.bend`) uses it.
F5  C06 `stage_go(0)` (a diagnosis in which every stage passes) reported
    `resource-exhausted`, a fuel event that never happened. It is now
    `invalid-input`, reason `internal-stage`. The audit's first reading,
    that `diag_brep` misses `brep_checked`'s recheck, is withdrawn: the
    recheck is implied by the orientation verdict (C04 §3 calls it
    redundant), so stage L agrees.
F6  C06 `evm` chose continue-or-halt with `Bool.pick`, which evaluates
    both arms: every node after a failure was still built. Probe: a
    40-node walk that halts at node 1 cost 40× a 1-node walk (0.40 s vs
    0.01 s). Repair: the decision is a parameter; the built list is
    accumulated in reverse (no append per node).
F7  C06 cache reuse matched the 64-bit node hash, which is linear in its
    words (`h·P + w`; also not FNV-1 as the contract said). Probe: two
    parts (height 10 and 9.998046874999227) have hash
    11712806376517700278; evaluating the second against the first's
    cache published the first's box. Repair: entries hold the full key
    and match exactly (sort-merge); the key also covers coordinates,
    profile points, hole specs and the transform matrix, which the hash
    left out; the root is found among the matched entries.
F8  C06 accepted duplicate node ids and duplicate param ids (the first
    silently won). Both are now `invalid-input`.
F9  C06 surface evaluators gated on `cy_valid`/`co_valid`/`to_valid` only;
    C03 requires a unit axis, and `qframe` assumes one. Probe:
    `trim_quad` on a cylinder with axis (0,0,2) returned ok. Repair:
    `ax_unit_ok` in all seven gates.
F10 C05 `region_key` unioned ids by repeated insertion (`O(n·m)`).
    Repair: concatenate, sort, deduplicate.
F11 C04 contract BN-8 row described the pre-R0.2 per-walk fuel. Rewritten.
F12 C03 contract §10/G6 claimed every published box contains the
    evaluated set. Probe: four controls at x = 0.1 give hull [0.1, 0.1];
    `bez3_eval` at t = 0.1 returns x one ulp above, at t = 0.3 two ulps
    below. The hull contains the exact curve. Contract restated, the
    counterexample pinned.
F13 C04 `push` is `O(n)` per entity (list stores). Not repaired: the
    store redesign belongs with the first builder that pushes many
    entities. Stated in MASTER_PLAN.
F14 C04 `ix_bound` ignored NURBS knot lists, while stage G evaluates
    NURBS edges with the caller's fuel. Probe: a two-vertex store with a
    cubic NURBS edge has bound 2; `brep_embed_c` returned 2 (decided
    invalid) at fuel 2 and 3 at fuel 100. Repair: the bound includes
    `nk + 1` for every NURBS edge.
F15 C05 nesting (R0.1) bucketed edges into √E slabs and scanned a whole
    slab per component: `m` nested squares cost `O(m²)`. Probe: 250 /
    500 / 1000 / 2000 nested squares 0.2 / 0.5 / 1.7 / 6.4 s. Repair: a
    vertical ray at `x − ε` from each component's minimum vertex, on a
    segment tree over the distinct vertex x-ranks with vertically sorted
    nodes (§5).
F16 C05 published a face that touches itself at a vertex as one loop
    through that vertex twice, although the contract (§2.2, §6)
    promises simple loops and GEOS hole parity. The new nesting
    family of the arrangement oracle found it: 13 of 600 cases, all
    pinched faces, and the predecessor's code gives byte-identical
    output on all 600, so the defect is C05's own, not F15's.
    Splitting each pinched loop at its repeated vertex reproduces
    shapely's (area, hole count) multiset in all 13. Repair: every
    walked cycle is split into simple cycles before orientation is
    certified (`cyc_split`: one sort of the cycle's origins, then a
    stack fold; a vertex that recurs off the stack publishes
    nothing). Probe: a square with a triangle touching its bottom
    edge at (2, 0) was one loop through `e11.0` twice; it is now the
    square with the triangle as a touching hole.

## 6. Host scheduler on the pin

R0.3's side scheduler (`0759b750`) was never on the pin. `02657a7e`
replays it onto upstream 2.0.35's pool, which keeps main-thread
participation, yield before sleep and the ring rewind. A turn wakes
one worker per further unit, each through its own slot, and a worker
spins before it sleeps; a frontier of at most `CUBE_T` tasks runs
listed turns that deal only units holding tasks; a drain with fewer
queued tasks than threads runs flat.

A stress run (bench programs at 16, 7, 3 and 2 threads, 800 runs)
found a race in the first replay: a worker whose claim ran past
an older turn's bound read the next turn's list, so two threads
drained one unit (two hangs, one fail-stop; `288da083` 0 of 800). A
listed turn now stores its list length with the turn's low byte, and
a stale claim takes no unit. With the fix: 2,400 runs (pm_map 1,200;
pm_tree, sol-truss-16, sol-grid-40, sol-chain-1000 300 each), 0 bad,
every output equal to the one-thread output.

Fork tests: every `tests/*/*.bend` with an expected output, built by
`288da083` and by `02657a7e` and run at 16, 4, 2 and 1 threads: 2,824
runs pass and none regress. 20 runs (gfx_clicks, gfx_window,
io_select_eintr, io_tcp_connect_black_hole, io_tcp_send_slow_peer)
need a display or a network peer and fail the same way on both; 843
