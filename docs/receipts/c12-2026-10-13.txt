## 5. Semantic bugs

Demonstrated kills (old behavior fails the named witness):

1. Reversed strings in the STEP reader (`sr_mkstr` applied a
   spurious `List.reverse`): every line, token, name, and entity
   body came out backwards, so all imports died with
   `step-no-solid`. Failing witness: probe `sr_sec_go` returned 0
   of 2 DATA lines before the fix, 2 after; law
   `mkstr_unreverses` fails on the old code (demonstrated
   `SOME PROOFS FAIL`), as do the `sec_extract`, `kind_si`, and
   `units_*` pins. Mutant `string builder un-reverses` is killed.
2. Zero stamp on parsed breps (`br_mk` set `stamp = 0u64`):
   `mk_brep` requires `0 < gen ≤ stamp`, so every import and
   reopen died with `import-validation-failed at brep stage
   stage-unknown` (all `ck_*` stages passed; only the index build
   refused). Failing witness: probe `brep_checked` returned
   `terr:invalid-input` before the fix, `tok` after; law
   `br_mk_stamp` and pin `ar_stamp` fail on the old code
   (demonstrated). Mutant `brep stamp covers its gens` is killed.
3. Entity-kind collision (`BREP_WITH_VOIDS` and `SI_UNIT` both
   mapped to kind 29): voided solids would have imported with
   their voids silently dropped. Failing witness: law
   `kind_voids` (expects 30) and neg journey `import.voids`
   (`step-voids-not-in-profile`). Fixed by moving voids to kind 30
   with an explicit refusal stage (`sr_parse_vd`).
4. Dead tol-import arm (`op_blob_tol` True branch returned
   `M.bad(..., "r2probe", ...)`): every `step_import` and tol
   archive import failed. Failing witness: `imp.box/hole/multi`
   journeys fail on the old code. Fixed by deleting the dead arm
   and delegating to `M.op_blob_pay`, the one general import
   mechanism; dead tag/dev parameters dropped.
