# C16.2 laws

Thirteen laws in three families over `src/c16/surf.bend` and the
`op_sw_open` / `op_patch` / `op_thicken_open` / `surf_rep` production
entries, following the C09 `closed_solid` pattern generalized to open
shells: every law quantifies over the production builder inputs and
reduces to `True` by case analysis on the input records, since use
structure never depends on F64 values.

## F1 — open boundary invariant (3 laws)

`open_shell` states faces-closed, per-edge use balance against a boundary-id
list (boundary edges used exactly once, interior edges once each way),
endpoints below the vertex count, and the Euler count with the builder's
topology: χ=0 for loft-open walls and sweep-open walls (tubes), χ=1 for patch
(disks). The boundary-id lists are the same functions the `surf` report uses
for edge names, so law and report cannot disagree.

- `loft_open_shell`, `swo_open_shell` (case-split on quarter count),
  `patch_open_shell`.

## F2 — counts and thicken closure (5 laws)

- `thicken_slab_closed`: the 6-face slab closes with χ=2.
- `thicken_duct_closed`, `thicken_sec_closed` (quarter case-split): the 16-face
  tubes close with χ=0, i.e. genus 1 through-channels — stated, not assumed.
- `surf_rows_len` (induction over boundary rows) and `surf_rows_nil`.

## F3 — refusals through production entries (5 laws)

Each law drives a representative out-of-domain value through the entry
the CLI and MCP call and pins the exact refusal record, quantifying
every input the refusal does not depend on.

- `sweep_angle_refused`: 45 degrees refuses
  `sweep-angle-not-certified` (unsupported) for all profiles, guides,
  twists, envs and node ids.
- `patch_degenerate_refused`: 16 control points with two identical
  rows refuse `patch-degenerate`; finiteness and row equality are
  bit-level, so the whole check normalizes.
- `surf_needs_open_refused`: `surf` on a box node refuses
  `surf-needs-open-shell`.
- `thicken_needs_open_refused`: `thicken-open` on a box node refuses
  `thicken-needs-open-shell`.
- `thicken_thickness_refused`: zero wall thickness refuses
  `degenerate-feature` for all point lists, intents, bodies, envs
  and node ids.

Four refusal codes carry no law: `lo` (loft planarity is decided
deep inside the C09 loft machinery after C07 evaluation),
`sp` (profile admission needs `prof_check` certification),
`tc` (rect/straight checks need F64 norms, midpoints and cross
products) and `ts` (shell minima need certified geometry) all
require F64 arithmetic the verdict kernel cannot compute. Pins
(`os_*`, `bnd_*`, `rect_*`, `duct_inner`, `sec_t`, gate tags) and
neg journeys (`loft.nonplanar`, `sweep.slant`, `thicken.curve`,
`thicken.consumes`) are their cover, and the old restatements are
deleted, not replaced.

## Mutants (one per refusal law)

- F1: flip a boundary use direction (balanced count breaks).
- F2: drop a surf row (length law breaks).
- F3: bad sweep angles, surf on solids, thickens of solids, zero
  thickness accepted, plus a patch-refusal reword (a `pa` gate flip
  would run a full concrete patch build in the checker, so the
  reword mutant pins the exact code string instead). The old curved-thicken
  mutant is retired: no passing law can reach the `tc` gate without
  restating it, so the mutant it guarded is replaced by the sweep-angle
  mutant above.

## Deviation notes

- F1 proves the use-table invariant the builders own; brep-level validity under
  the open profile is evidenced by pins (stage verdict vectors) and E2E, since
  the checker cannot unfold the C04 validator. Same split as C16.1's F1 note.
- Euler characteristics differ per builder (0, 1, 2) and are stated per law;
  there is no shared genus assumption.
