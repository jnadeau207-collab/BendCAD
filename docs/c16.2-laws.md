# C16.2 laws

Seventeen laws in three families over `src/c16/surf.bend`, following the C09
`closed_solid` pattern generalized to open shells: every law quantifies over
the production builder inputs and reduces to `True` by case analysis on the
input records, since use structure never depends on F64 values.

## F1 — open boundary invariant (3 laws)

`open_shell` states faces-closed, per-edge use balance against a boundary-id
list (boundary edges used exactly once, interior edges once each way),
endpoints below the vertex count, and the Euler count with the builder's
topology: χ=0 for loft-open walls and sweep-open walls (tubes), χ=1 for patch
(disks). The boundary-id lists are the same functions the `surf` report uses
for edge names, so law and report cannot disagree.

- `loft_open_shell`, `swo_open_shell` (case-split on quarter count),
  `patch_open_shell`.

## F2 — counts and thicken closure (5 laws)

- `thicken_slab_closed`: the 6-face slab closes with χ=2.
- `thicken_duct_closed`, `thicken_sec_closed` (quarter case-split): the 16-face
  tubes close with χ=0, i.e. genus 1 through-channels — stated, not assumed.
- `surf_rows_len` (induction over boundary rows) and `surf_rows_nil`.

## F3 — refusal closure (9 laws)

One law per gate: a `False` input produces the exact `GR_no` term the CLI
renders (`lo_go_false`, `sa_go_false`, `sp_go_false`, `pa_go_false`,
`tc_go_false`, `ts_go_false`, `su_go_false`, `th_go_false`, `dg_go_false`).
Gate predicates (rect detection, row distinctness, inner-channel validity) are
pinned, not proven, exactly as in C16.1.

## Mutants (one per family)

- F1: flip a boundary use direction (balanced count breaks).
- F2: drop a surf row (length law breaks).
- F3: accept a curved thicken (curvature gate breaks).

## Deviation notes

- F1 proves the use-table invariant the builders own; brep-level validity under
  the open profile is evidenced by pins (stage verdict vectors) and E2E, since
  the checker cannot unfold the C04 validator. Same split as C16.1's F1 note.
- Euler characteristics differ per builder (0, 1, 2) and are stated per law;
  there is no shared genus assumption.
