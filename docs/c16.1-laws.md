# C16.1 sheet metal — laws

11 laws in 3 families over `src/c16/sheet.bend` and the `op_sheet` /
`flat_sc` production entries. Every law passes `tools/laws/check.sh`
under `--check-only` and `--verdict`; every family kills its planted
mutants in `tools/laws/mutate.py` (one per refusal law).

## F1 profile topology (2)

- `sh_loop_closed`: for every profile key, dimension, radius, hem
  and rotation argument, the produced profile and its 180-degree
  rotation are linked (head starts at the path start, every
  segment starts where the previous ends) with every endpoint
  index below the point-table length. Proved by case over the 12
  finite keys; the rotation shares segments definitionally.
- `sh_rot_len`: rotation preserves the point count (list
  induction, C15 rewrite form).

Helpers `sg_a/sg_b/below/linked/idx_closed` live in LAWS.bend
(C09 precedent). Mutant: loop edge skips its successor.

## F2 flat-pattern counts (3)

- `flat_rows_len`: one row per bend (induction over the
  production recursion `rows_go`, whose index the law carries).
- `flat_rows_nil`: no bends, no rows.
- `flat_legs_flat`: the blank develops to its single length run.

Mutant: rows drop every bend row.

## F3 refusals through production entries (6)

Each law drives a representative out-of-domain value through the
entry the CLI and MCP call (`M.op_sheet` for builds, `C.flat_sc`
for the flat query) and pins the exact refusal record — code, fix,
what, node rendering and FailKind — quantifying every input the
refusal does not depend on. Inputs evaluated by earlier gates stay
representative-concrete (a flat 120x80 blank, radius 2); the kernel
never reduces untaken match arms, unused strict lets or ignored call
arguments (probed), so later gates and uninspected inputs stay
symbolic.

- `bend_base_refused`: any base id against an empty design refuses
  `bend-base-not-admitted` (invalid).
- `bend_fin_refused`: zero thickness refuses `degenerate-feature`
  for all edges, angles, intents, bodies, envs and node ids.
- `bend_angle_refused`: 45 degrees refuses
  `bend-angle-not-certified` (unsupported) for all edges, intents,
  bodies, envs and node ids.
- `bend_edge_refused`: edge 4 refuses `bend-edge-not-admitted`
  (unsupported); the radius also violates R/T, which pins the
  edge-before-rt first-wins order and keeps the mutant kill fast.
- `hem_len_refused`: a 120 hem on a 100 blank refuses
  `hem-consumes-face`; the flat-hem leg needs no arithmetic, so the
  whole chain normalizes.
- `flat_kzone_refused`: the inverted zone (0.7, 0.3) refuses
  `bad-k-zone` for all chains, envs and node ids.

Mutants, one per law: bad angles, missing bases, degenerate blanks,
bad edges accepted, plus hem-refusal and k-zone rewords. A `len`
gate flip would run a full concrete sheet build in the checker, and
a `k` gate flip sends the checker into a 20-minute hole on the
symbolic flat report, so both reword mutants pin the exact code
string instead (the flip was measured, then replaced). The `rt`
(R/T bound)
and `size` (blank vs twice outer radius) gates need F64
division/multiplication, which the verdict kernel cannot compute,
so they carry no law: pins (`allow_i`, volumes, gate tags) and neg
journeys (`bend.tight`, `bend.toosmall`) are their cover, and the
old `rt_go_false` / `size_go_false` restatements are deleted, not
replaced. Grammar paths (third bend, Z, hem-after-hem) are likewise
E2E-only (`bend.third/zshape/sameend/afterhem`,
`hem.afterhem/on180`).

## Evidence split

Proven: loop linkage + index validity, row/run counts, refusal
records through production entries. Pinned (fixed inputs,
bit-exact): gate outcomes and first-wins order, chain selectors,
seg/arc/face counts, volumes, allowances, developed intervals,
rendered fields, op tags, parse shapes, boundary values. E2E: 3D
solid closure per profile (check-ok, exact faces/cylinders/volumes/
bboxes), oracles, param propagation, STEP/tessellation independent
readers, every refusal verbatim with no publication.

## Deviation from the plan

The plan sketches F1 as `bend_closed_solid`/`hem_closed_solid`
in the C09 `closed_solid` pattern. That pattern fits direct
`pack()` construction; C16.1 builds through `op_prism`
(fillet-edge precedent), where 3D closure is inherited, not
constructed. Stating `closed_solid` over prism output would
unfold the whole prism builder symbolically (the AGENTS.md
overflow warning); writing parallel explicit builders just for
laws would prove a model, not the shipped geometry. F1 instead
proves the real 2D invariant the builders own (linkage +
validity, quantified over every production profile) and leaves
solid closure to the inherited certificate plus per-profile
runtime evidence. The added `bend-consumes-face` refusal and its
gate law close the dimensional gap the plan list left open.
