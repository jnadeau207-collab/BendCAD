# C16.3 intent — why blade sections look like this

G5 needs a fan/compressor blade an agent can trust: true airfoil
sections, a real ruled solid, and section properties with honest
certificates. C16.3 does that with two verbs and one query, and refuses
everything it cannot certify.

The NACA 4-digit family is the smallest section vocabulary with an
analytic closed form: three integers pick camber, camber position and
thickness, and the half-thickness, camber and normal-offset formulas
need only sqrt — no trig, no iteration, bit-exact against an independent
mirror. The digit gate doubles as the leading-edge-radius gate: T 06 is
the thinnest section the packet measures as certifiable, and anything
thinner refuses by the digit name. The section publishes as a unit-span
slab through the same ruled builder as blades, so one code path carries
both and the slab volume is exactly the section area times one.

Blade owns the stacking schedule and checks it: equal points and chord
across sections, twist from the certified interval trig evaluator,
taper as an exact tip-chord percent. Twist about the quarter-chord
stacking axis with taper about the leading edge gives the leaned stack;
the deviation is reported, not hidden. Volume is the prismoidal rule,
exact for ruled walls by Simpson on the quadratic area schedule — the
frustum rule agrees to float rounding on untapered stacks and the oracle
pins both.

`blade` reports intervals, never points: area, centroid, thickness and
camber contain the stored brep's values by interval-arithmetic
construction, and the E2E suite checks independent evaluations land
inside. Blades are closed solids, so the whole kernel — measure, check,
tessellate, STEP, archive, clearance, PMI stacks — applies unchanged;
features and zones answer the existing refusals because a ruled loft is
neither extruded nor zonable.
